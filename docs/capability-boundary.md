# 能力边界

## 1. 已验证能力

本公开案例和流程材料覆盖以下受监督步骤：

- Task 创建的流程记录方式。
- Worker 调度的角色和交接约定。
- Worktree 隔离的协作方式。
- QA 独立验收（含 Node VM 场景测试和真实浏览器补验）。
- Reviewer 验证和结论记录。
- 从候选版本到 Delivery 的交付闭环说明。
- 掉线恢复子步骤（checkpoint 写入/读取，新进程读取验证）。
- 进程重启恢复子步骤（新进程读取检查点内容一致性核验）。
- 分支冲突/rebase 演练（隔离仓库中实际产生 UU 冲突状态）。
- 备份还原并 sha256 核验。
- 多 Worker 文件所有权不重叠的并行调度结构。

这些内容表示流程材料中有对应示例或模板，不表示本仓库提供了实现这些能力的运行时服务。子步骤通过不等同于完整流程验证——完整证明需要跨越原始中断事件和实际续接运行的端到端证据。

## 2. 待验证 / BLOCKED 能力

以下能力在实际测试中记录了真实阻断，不应从本仓库推断为已验证：

- **原生审批（approve/reject 反馈）**：CODEX_HOME token 对 api.openai.com 返回 HTTP 401，审批层不可达，无批准/拒绝及理由反馈的实测证据。
- **Session resume（会话交接）**：目标 thread_id 返回 "no rollout found"，原会话不可续接。
- **Sandbox 权限边界实测**：codex exec 在到达 sandbox 层前已因 auth 失败退出，write-block 未被实际触及。
- **预算/超时控制实测**：同上，token 上限和 timeout_ms 均未被真实触及。
- **掉线/重启完整续接**：子步骤（检查点读写）通过，但实际中断→恢复→任务完成的完整端到端流程未经原始证据覆盖。
- **实际执行并行证据**：Dispatch createdAt 差距 2 分钟，dispatched_at=null，精确执行窗口不可查。

## 3. 未验证能力

以下能力不应从本仓库推断为已实现：

- 自动生产发布。
- 自动权限批准。
- 无人监督运行。
- 跨组织的凭证和数据治理。

## 4. 原则

**Agent 执行，人类决策。**

Agent 可以在明确范围内执行任务和生成证据，但人类仍负责权限、敏感数据访问、外部写入、候选合并和发布决定。无法核实的能力应标记为待验证或 `BLOCKED`，不能用文案替代运行证据。
